# Pummy plugin audit — October 12, 2026

Audited the existing hosted Pummy Adaptive Test and its authoritative `pummy-site` checkout. The release retains the Site/plugin identity, audience, D1 and R2 bindings. Live verification used read-only course operations; mutation and failure tests used disposable local databases and mock object storage.

## Fixed

| Finding | Repair | Evidence |
| --- | --- | --- |
| Files over 200 questions were rejected although courses support 500; a 204-question export could not be restored. | Import JSON banks in batches of at most 200, up to the 500-question course capacity. Retain each batch receipt across retries. | 500-question export/restore integration test; 204-question real-browser import with a lost second-batch response. |
| JSON import generated new request IDs on every retry, allowing duplicate courses or questions after uncertain saves. | Keep the import plan in the current panel until completion. Re-selecting the same file resumes confirmed batches and retries uncertain writes with the same IDs. | Lost initial-import and append response tests; one course and exactly 204 questions after recovery. |
| Exported questions without page numbers contained `page: null`, which the importer rejected. | Accept an absent/null page while validating supplied page numbers as positive integers. | Full exported-bank roundtrip and browser JSON import. |
| Appended question banks ignored supplied concept schedules. | Restore schedules only for newly created concepts; retain existing concept progress and the active exam. | 500 restored concept schedules and active-exam preservation tests. |
| MCP parsed an unbounded cloned request before its size check; browser requests counted characters rather than UTF-8 bytes. | Limit streams to 1,500,000 bytes before JSON parsing, cancel oversized streams, and return proper JSON-RPC parse errors. | No-Content-Length, multibyte UTF-8, early cancellation, declared oversize and HTTP transport tests. |
| Development dependencies reported one high and four moderate advisories. | Update Drizzle ORM/Kit and override the deprecated loader's nested esbuild with the patched build dependency. | Clean `npm ci --ignore-scripts`, zero npm audit vulnerabilities, and Drizzle generation against a disposable migration copy with no schema changes. |

The MCP UI resource advances to v17, retaining earlier aliases. Added a single command, `npm run test:all-browser`, for all seven browser suites, plus individual upload, recovery and bank-import commands.

## Remaining limits and external dependencies

1. **Automatic PowerPoint conversion:** production has no configured `PRESENTATION_CONVERTER_URL` / `PRESENTATION_CONVERTER_TOKEN`, and this machine has no LibreOffice executable at the standard installation path. Original upload, companion-PDF slide viewing and PPTX exports passed. Actual native PowerPoint-to-PDF conversion was not run. Enable the authenticated converter described in `INTERACTIVE-TUTOR.md` to support this automatically; no placeholder service or credentials were installed.
2. **Anonymous sign-in:** recent production logs contain 404s on the platform-owned `/signin-with-chatgpt` route. The existing signed-in browser and authenticated MCP calls work. Sites owns that route; no replacement OAuth handler was added. First-time anonymous sign-in remains unverified end to end.
3. **Conversation generation:** host handoffs and generated-response lifecycles were tested in a simulated MCP host. No live student's answers, exam progress or question banks were changed to test real model generation.
4. **Existing processing limits:** sources remain limited to 30 excerpts of at most 60,000 characters, objectives to 200, saved questions/history to 900 KB and each HTTP/tool request to 1.5 MB. Very large reference/image payloads may require smaller imports. JSON retry receipts survive in the current open panel; closing/reloading it discards the client import plan.
5. This is a broad code, integration, browser and deployment audit, not an exhaustive proof of every possible browser, document or concurrency scenario.
