# Tutor screen docking and audio themes

The floating tutor control now anchors to the visible viewport rather than the presentation rectangle. All four corners work with dragging or Alt + arrow keys. The saved corner is reused across reopen/reload. Scrolling, resizing, visual viewport changes and native fullscreen reposition the control. The expanded bar wraps within phone widths, and status text grows away from the bottom edge. Cancelled drags return to the saved corner. In an embedded host, the available screen is the app's own frame; a web app cannot float controls outside its host frame.

Slide audio now uses the current theme for panel, heading, filenames, download buttons, hover/focus states and error messages. Native audio controls inherit the light/dark color scheme. Long filenames and narrow screens wrap without horizontal overflow; multiple tracks can scroll inside the panel. The original PowerPoint and embedded audio download actions are preserved.

Verification: a dedicated disposable browser suite checks all four screen corners by keyboard and drag; cancellation, scrolling, phone resize, actual native fullscreen, reopening/reloading, audio playback, and button contrast in navy, warm, light, custom light and custom dark. Existing editor, explanation bridge and tutor browser suites also passed, covering annotations, save/recovery, exports and conversation handoffs. No student exam answers were submitted or changed. Course state remains identical in the regression harnesses.

The MCP interface resource advances to v20 with v19 and all earlier aliases retained. Site, plugin, audience, storage bindings and database schema are unchanged. No new dependency is required.

Proof screenshots are generated in `work/docking-qa/` (ignored test artifacts). Native media controls are browser-drawn, so their exact icons and spacing vary by browser.
